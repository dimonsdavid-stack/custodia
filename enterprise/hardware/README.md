# Hardware integration contract

The enclave binary requests a real attestation document from `/dev/nsm` using the AWS NSM API and carries fresh 32-byte challenges over AF_VSOCK. There is no software attestation fallback. The host gateway verifies the Nitro certificate chain against an explicitly mounted, independently authenticated AWS root PEM, verifies COSE ES384, rejects debug measurements, checks freshness and nonce, then signs the existing containment assertion using OpenSSL 3's external PKCS11 provider. RSA HSM keys with SHA256 PKCS1 signatures are required for compatibility with the backend verifier. The gateway does not generate, export, or emulate HSM keys.

Required host variables: `ENCLAVE_CID`, `NITRO_POLICY_FILE`, `NITRO_ROOT_PEM`, `ASSERTION_PKCS11_KEY_URI`. The policy JSON requires `pcrs` (numeric string indices mapped to 96-character SHA384 hex), `issuer`, `audience`, and `subject`. These must exactly match backend `ATTESTATION_PCRS`, `ATTESTATION_ISSUER`, `ATTESTATION_AUDIENCE`, `ATTESTATION_SUBJECT`. `ATTESTATION_PUBLIC_KEY` is the matching HSM public key PEM and `ATTESTATION_URL` is the HTTPS Envoy ingress `/attest`. Construct a policy from the EIF build measurements; never accept measurements supplied by the attested runtime itself as policy.

Deploy on an enclave-enabled Linux EC2 parent with the Nitro allocator configured for two CPUs and at least 1536 MiB enclave memory. Install the audited vendor OpenSSL PKCS11 provider and its PKCS11 module before starting the gateway. Provision its credentials through the provider's protected configuration. PIN values in the key URI are refused. Grant the runtime's nonroot UID access to `/dev/nsm` via the EIF device configuration; validate this on actual hardware. Build with `build-eif.sh`, review and approve its measured output, then run `run-eif.sh`. Do not enable debug mode.

The EIF image now includes the NSM service and PDF sanitizer. It runs the PDF sanitizer on AF_VSOCK port 5006 alongside attestation on 5005; use workers/redaction/gateway.py on the parent host for mTLS forwarding. Rebuild and approve all PCRs after this image change. The full Next.js API, structured text sanitizer and database do not run inside the enclave; do not claim full SaaS hardware isolation. No cluster deployment or live attestation was performed in this workspace.

References: AWS NSM API https://github.com/aws/aws-nitro-enclaves-nsm-api ; attestation verification https://docs.aws.amazon.com/enclaves/latest/user/verify-root.html ; COSE format https://github.com/aws/aws-nitro-enclaves-nsm-api/blob/main/docs/attestation_process.md ; AF_VSOCK API https://docs.rs/vsock/latest/vsock/ ; Envoy SDS https://www.envoyproxy.io/docs/envoy/latest/configuration/security/secret .

The PDF worker accepts only parent CID 3, enforces frame limits, executes parsing in a bounded child process and kills the measured container on a stuck native parser. The parent gateway has no local sanitization fallback. These AF_VSOCK bindings require live Nitro hardware and have not been executed here. Nonroot /dev/nsm device permissions must be validated in the final EIF.
