# Document boundary

Supported upload inputs are strict UTF-8 text, JSON, and searchable text-only PDF up to 5 MiB. PDF parsing runs behind TLS1.3 mutual certificate verification in a bounded Python worker; production enclaves forward over AF_VSOCK to the measured PDF process. PDF raster flattening produces a new document with no source metadata, annotations, attachments or hidden searchable text. Input images and unsearchable pages are rejected until verified OCR and human image review are implemented. Text expressions detect selected SSN/EIN/email/phone formats and explicit literal terms; structured JSON additionally removes values of selected sensitive keys. Detection is not a universal guarantee about unknown sensitive data or legal exemptions.

All originals, sanitized artifacts and policies are encrypted with AES-256-GCM, tenant-derived HKDF keys and tenant/document/purpose/key-ID AAD. Filename text is sanitized. The relational metadata, source/sanitized hashes and bounded count reports remain visible only through forced tenant RLS. No source body, credential, sensitive term or full document value is logged. The service uses bounded request memory rather than plaintext disk caches.

A named identity with documents:approve must explicitly confirm a reviewed document version before export. documents:write permits upload; documents:read permits a sanitized preview and list; documents:export permits approved download. Source-original download is not exposed. Approval and export append immutable signed event payloads and retain the signing key ID. Document audit is separate from the unchanged core request ledger.

CSV exports neutralize spreadsheet formula prefixes and quote fields. XLSX writes literal cells through ExcelJS and rejects oversized cells. JSON-LD uses a local inline context and sanitized entries. Each export has SHA256, HMAC signature, signed-proof and key-ID headers; an authorized recipient verifies the exact file digest against the signed proof. Files are not password-encrypted spreadsheet formats; authentication, TLS and encrypted persistence protect custody. PDF export only returns the flattened artifact. Exporting structured data from a flattened PDF requires reviewed OCR and is deliberately rejected.

Configuration: DOCUMENT_ENCRYPTION_KEYS is a JSON keyring of retained key IDs to exactly 32-byte hex values, DOCUMENT_KEY_ID selects the active key. REDACTION_WORKER_URL is the actual HTTPS /redact service. REDACTION_CLIENT_CERT/KEY and REDACTION_SERVER_CA must be trusted short-lived deployment certificates, never generated fallback identities. TLS private keys in Node memory are not represented as non-exportable HSM keys.

Native PDF dependency is PyMuPDF, distributed under AGPL or a commercial license. Select and satisfy the applicable distribution license before commercial release. The worker uses Linux memory/core-dump limits; its container also needs CPU/memory/PID limits and a supervisor that restarts on parser timeout. Human approval remains required because regex/text geometry cannot establish completeness of legal review.

POST /api/v1/documents takes the binary body, Content-Type, x-request-id UUID, URL-encoded x-document-name and base64url JSON x-redaction-policy. GET lists documents or reads sanitized preview with id and format=preview. PATCH approves {id,version,confirmed:true}. GET with format csv/xlsx/jsonld/pdf requires prior approval and export permission. /documents is the organization-authenticated upload/review/export interface.
